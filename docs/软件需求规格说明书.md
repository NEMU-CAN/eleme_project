\## 2 总体描述



\### 2.1 产品概述

系统覆盖外卖下单主链路：顾客登录 → 浏览商家与食品 → 加入购物车 → 选择收货地址下单 → 查看订单。后端提供 RESTful 接口，前端按接口渲染页面。当前阶段商家信息与食品由系统预置数据提供，商家管理功能放入阶段2。



\### 2.2 用户角色

| 角色 | 说明 |

|---|---|

| 顾客 | 系统核心用户：登录、浏览、购物车、下单、查订单 |

| 游客 | 未登录浏览（当前未强制登录校验，接口路径均显式携带 userId） |

| 商家/管理员 | 阶段2 引入，维护店铺/食品信息（阶段1 未实现） |



\### 2.3 运行环境

\- 后端：JDK8、SpringBoot + MyBatis + Lombok；数据库 MySQL 8。

\- 前端：Vue3 + TypeScript + Vite。

\- 测试/联调：JUnit5、MockMvc、ApiFox/Postman。

\- 部署形态：本地前后端分离运行，浏览器访问。



\### 2.4 设计约束

1\. 后端分层：Controller → Service（interface+impl）→ Mapper，实体 entity / 展示 vo / 统一返回 result。

2\. 接口遵循 RESTful 资源命名（名词、HTTP 方法语义正确），统一返回体与错误码。

3\. 订单总价由服务端根据食品价格计算，不信任前端传值。

4\. 所有开发内容 Git 提交留痕。

5\. 任务书要求全程 TDD（见 6.3 现状说明）。



\### 2.5 范围：阶段1（已实现）与阶段2（迭代规划）

| 模块 | 阶段1（本期实现） | 阶段2（迭代规划，未实现） |

|---|---|---|

| 用户 | 注册、登录、查看个人资料 | 资料/密码修改、登录态与鉴权（token） |

| 商家/店铺 | 商家列表（按分类过滤）、商家详情、某商家食品列表 | 商家注册、营业/休息/临时闭店状态、商家信息维护 |

| 食品 | 按商家浏览列表（价格/图片/备注） | 食品增删改、食品分类、库存展示 |

| 购物车 | 列表（可按商家过滤）、加入（同用户同店同食品累加）、改数量、删单条、按条件清空 | 商品失效/售罄提示 |

| 收货地址 | 按用户增删改查 | 默认地址、手机号格式校验 |

| 订单 | 从购物车按商家创建、订单列表（按商家/状态过滤）、订单详情（含商家/地址/明细） | 支付动作、取消、退款、更多订单状态 |

| 通用 | 统一返回 {code,msg,data}、字段级错误明细、全局异常处理 | 接口版本前缀 /api/v1、统一日志与请求拦截 |

\## 3 功能需求



\### 3.1 用户模块

功能：注册、登录、查看个人资料。



业务规则：

\- 注册：`userId` 为主键且全局唯一，采用业务编码（如 u10001）；密码非空；性别 1 男 / 0 女；新用户 del\_flag 取正常值（取值定义见 4.1）。

\- 登录：校验 userId + password；del\_flag 为删除态的用户禁止登录；成功后返回用户资料（不含密码）。

\- 资料查询：按 userId 返回本人信息（id/name/sex/avatar/delFlag）。



正常流程：注册成功 → 登录成功 → 查看本人资料。

异常/边界：

\- 用户编号已存在（重复注册）→ 409 资源冲突。

\- 密码错误 / 用户不存在 → 401（code 40101）。

\- 删除态用户登录 → 拒绝。

\- 查询不存在的用户 → 404。



\### 3.2 商家与食品模块（顾客端浏览）

功能：首页/列表展示商家，进入商家详情查看食品并点选。



业务规则：

\- 商家列表可按点餐分类 order\_type\_id 过滤；字段含名称、地址、介绍、图片、分类、起送价、配送费、备注。

\- 商家详情返回商家完整信息；某商家食品列表返回食品名称/介绍/图片/价格/备注。

\- 当前阶段商家为系统预置只读数据（由 data.sql 提供），无商家管理接口。



异常/边界：

\- 商家不存在 → 404。

\- 某商家下无食品 → 返回空列表。

\- 分类参数非法 → 400，data 返回字段级错误。



\### 3.3 购物车模块

功能：顾客购物车管理，以“用户 + 商家”维度组织。



业务规则：

\- 购物车条目含 food\_id、business\_id、user\_id、quantity，真实落库于 cart 表。

\- 加入购物车：同一 user\_id + business\_id + food\_id 已存在时\*\*累加数量\*\*；quantity 缺省默认 1。

\- 查询购物车支持按 business\_id 过滤，只看某家店。

\- 删除支持两种：按 cartId 删除单条；按条件（business\_id / food\_id）批量清空。

\- 数量修改 quantity ≥ 1。



异常/边界：

\- quantity < 1 → 400。

\- 食品/商家不存在 → 404。

\- 访问不属于当前 user 的购物车条目 → 404（视为资源不存在，不暴露存在性）。



\### 3.4 收货地址模块

功能：维护收货地址，供下单选择。



业务规则：

\- 地址属于某个 user\_id；必填联系人姓名、联系电话、详细地址；联系人性别 1 男 / 0 女。

\- 增删改查均以该用户为作用域。



异常/边界：

\- 必填项缺失/非法 → 400，字段级错误明细。

\- 地址不存在 → 404；操作他人地址 → 404。



\### 3.5 订单模块

功能：从购物车按商家创建订单，查看订单列表与详情。



业务规则：

\- 创建订单请求体仅传 `businessId` 与 `daId`（收货地址）；后端从该用户购物车中取出\*\*该商家\*\*下的条目生成订单与明细（orderdetailet）。

\- \*\*订单总额 order\_total 由服务端按“食品单价 × 数量”重新计算\*\*，不信任前端传价，防篡改。

\- 订单创建后建议清理该商家对应购物车条目（与后端实现核对，见 8 待确认）。

\- 订单状态 order\_status：0 未支付（默认）、1 已支付。当前阶段无支付动作接口，状态由预置/后续产生。

\- 订单列表支持按商家、订单状态过滤；订单详情返回订单主信息 + 商家 + 收货地址 + 明细（明细含食品信息）。



正常流程：加购 → 选商家与地址创建订单（201）→ 订单列表可见 → 详情含明细。

异常/边界：

\- 购物车为空 / 该商家下无条目 → 409（code 40901）。

\- daId 不属于该 user → 400/404。

\- 地址不存在 → 404。



\### 3.6 前端页面与主流程（已实现，基于 mock）

前端已完成“首页 → 商家列表 → 商家详情 → 结算 → 支付 → 订单 → 个人中心”交互闭环（登录/注册/404 已补齐），当前由本地 mock 与状态层驱动并 localStorage 持久化。后续通过替换 mock/数据读写层接入真实接口。

与后端现状的差距：前端支付/订单状态流转交互已做（模拟），后端支付与状态变更接口属阶段2——见 8 待确认。



\## 4 数据需求



\### 4.1 表结构总览（以真实 tables.sql 为准，共 7 表）

| 表 | 主键 | 关键字段 | 说明 |

|---|---|---|---|

| user | id varchar(20) | password, name, sex(1男/0女), avatar, del\_flag | \*\*del\_flag：1=正常，0=删除\*\*（默认 1，见 tables.sql 注释） |

| business | id int 自增 | name, address, description, image(mediumtext), order\_type\_id, start\_price, delivery\_price, remark | 商家/店铺；无营业状态字段（阶段2 补充） |

| food | id int 自增 | name, description, image(mediumtext), price, business\_id, remark | 无分类/库存字段（阶段2 补充） |

| cart | id int 自增 | food\_id, business\_id, user\_id(varchar20), quantity | 购物车落库 |

| deliveryaddress | id int 自增 | contact\_name, contact\_sex, contact\_tel, address, user\_id | 收货地址 |

| orders | id int 自增 | user\_id, business\_id, order\_date(varchar), order\_total decimal(7,2), address\_id, order\_status(0/1 默认0) | 订单主表 |

| orderdetailet | id int 自增 | order\_id, food\_id, quantity | 订单明细 |



\### 4.2 数据约定

\- 金额单位元，保留两位小数（decimal）。

\- 图片字段 mediumtext，当前存 base64（联调优化见 8）。

\- 订单时间 order\_date 为 varchar(20)，格式 yyyy-MM-dd HH:mm:ss。

\- 表间未建物理外键，归属与完整性校验在 Service 层完成。



\### 4.3 测试数据

使用统一 data.sql：覆盖多商家、多分类、若干食品/地址/购物车/订单，金额与明细一致，供前端展示、接口联调与交叉验收演示。

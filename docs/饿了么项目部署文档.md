# 饿了么项目部署文档

## 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 1.0 |
| 编写日期 | 2026年9月03日 |
| 适用范围 | 本地开发部署和 Linux 服务器部署 |
| 项目组成 | Vue 前端 Spring Boot 后端 MySQL 数据库 |

## 1 部署说明

项目包含三个部分：

- `frontend`：Vue 3 和 TypeScript 单页应用，使用 Vite 构建。
- `backend`：Java 21 和 Spring Boot 后端，使用 MyBatis 访问 MySQL。
- `new-resouces/饿了么.sql`：与当前后端实体匹配的数据库结构和演示数据。

后端默认监听 `8080` 端口，上下文路径为 `/api`。前端开发服务器监听 `5173` 端口，并把 `/api` 请求转发到 `http://localhost:8080`。生产环境由 Nginx 托管前端静态文件，并将 `/api` 转发给后端。

## 2 环境要求

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 及以上或主流 Linux 发行版 | 生产环境示例使用 Linux |
| JDK | Java 21 | `backend/pom.xml` 指定 Java 21 |
| Node.js | 22.18.0 或 24.12.0 及以上 | 以 `frontend/package.json` 为准 |
| npm | 随 Node.js 安装 | 使用 `npm ci` 按锁文件安装依赖 |
| MySQL | MySQL 8.0 推荐 | 数据库名称默认为 `elm` |
| Nginx | 1.20 及以上推荐 | 仅生产部署需要 |

部署前用以下命令确认环境：

```bash
java -version
node -v
npm -v
mysql --version
```

## 3 目录说明

├─ backend                         后端工程
│  ├─ src

## 4 数据库初始化

### 4.1 创建数据库

先登录 MySQL：

```bash
mysql -u root -p
```

创建数据库：

```sql
CREATE DATABASE elm
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

数据库脚本没有 `CREATE DATABASE` 和 `USE`，导入时必须指定 `elm` 数据库。

### 4.2 导入结构和演示数据

Windows PowerShell：

```powershell
Get-Content -Raw -Encoding UTF8 ".\new-resouces\饿了么.sql" |
  mysql -u root -p --default-character-set=utf8mb4 elm
```

Linux：

```bash
mysql -u root -p --default-character-set=utf8mb4 elm < new-resouces/饿了么.sql
```

`new-resouces/饿了么.sql` 包含表结构和演示数据，只能在空数据库中执行一次。重复导入会因表或主键已经存在而失败。

### 4.3 验证数据库

```sql
USE elm;
SHOW TABLES;
SELECT COUNT(*) FROM user;
SELECT COUNT(*) FROM business;
SELECT COUNT(*) FROM food;
```

导入后应看到这些表：

- `user`
- `business`
- `business_admin`
- `taste`
- `food`
- `cart`
- `delivery_address`
- `orders`
- `order_detail`

不要使用 `docs/tables.sql` 初始化当前运行数据库。该文件保留了早期表名和字段结构，与当前后端模型不完全一致。

## 5 后端配置

### 5.1 默认配置

后端配置文件位于 `backend/src/main/resources/application.yaml`。仓库内的默认值适合本地开发：

| 配置 | 默认值 |
| --- | --- |
| 服务端口 | `8080` |
| 上下文路径 | `/api` |
| 数据库地址 | `jdbc:mysql://localhost:3306/elm` |
| 数据库用户 | `root` |
| 数据库密码 | `1234` |
| JWT 有效期 | `24` 小时 |

### 5.2 环境变量

生产环境不要直接修改并提交 `application.yaml` 中的密码和密钥。Spring Boot 支持用环境变量覆盖配置：

| 环境变量 | 对应配置 | 示例 |
| --- | --- | --- |
| `SERVER_PORT` | `server.port` | `8080` |
| `SPRING_DATASOURCE_URL` | `spring.datasource.url` | `jdbc:mysql://127.0.0.1:3306/elm?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai` |
| `SPRING_DATASOURCE_USERNAME` | `spring.datasource.username` | `eleme_app` |
| `SPRING_DATASOURCE_PASSWORD` | `spring.datasource.password` | 使用高强度密码 |
| `APP_JWT_SECRET` | `app.jwt.secret` | 至少32字节的随机字符串 |
| `APP_JWT_EXPIRE_HOURS` | `app.jwt.expire-hours` | `24` |

Linux 环境变量文件示例 `/etc/eleme/backend.env`：

```dotenv
SERVER_PORT=8080
SPRING_DATASOURCE_URL=jdbc:mysql://127.0.0.1:3306/elm?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
SPRING_DATASOURCE_USERNAME=eleme_app
SPRING_DATASOURCE_PASSWORD=替换为数据库密码
APP_JWT_SECRET=替换为至少32字节的随机密钥
APP_JWT_EXPIRE_HOURS=24
```

不要把该文件提交到 Git。在 Linux 上将权限设为仅 root 可读写：

```bash
sudo chown root:root /etc/eleme/backend.env
sudo chmod 600 /etc/eleme/backend.env
```

## 6 本地开发部署

### 6.1 启动后端

进入后端目录：

```powershell
cd backend
```

Windows：

```powershell
.\mvnw.cmd spring-boot:run
```

Linux 或 macOS：

```bash
chmod +x mvnw
./mvnw spring-boot:run
```

Spring Boot 启动完成后访问：

```text
http://localhost:8080/api/tastes
```

这是公开接口，用于检查后端是否启动，以及数据库连接是否正常。

### 6.2 启动前端

另开一个终端并进入前端目录：

```powershell
cd frontend
npm ci
npm run dev
```

浏览器访问 Vite 输出的地址，默认是：

```text
http://localhost:5173
```

开发模式下，`frontend/vite.config.ts` 会把浏览器发出的 `/api` 请求转发到 `http://localhost:8080`。

### 6.3 本地验证

本地检查：

1. 打开 `http://localhost:8080/api/tastes`，确认返回 JSON。
2. 打开 `http://localhost:5173`，确认首页可以显示。
3. 使用演示账号登录，确认请求没有出现 401 或 500。
4. 打开店铺详情，确认商家、菜品和库存能够加载。
5. 新增一个收货地址并完成一次下单和模拟支付。
6. 使用商家账号进入商家中心，检查订单、菜品和店铺资料页面。

## 7 生产构建

### 7.1 构建后端

Windows：

```powershell
cd backend
.\mvnw.cmd clean package
```

Linux：

```bash
cd backend
chmod +x mvnw
./mvnw clean package
```

构建成功后生成：

```text
backend/target/backend-0.0.1-SNAPSHOT.jar
```

已经单独完成测试时，可以跳过测试再打包：

```bash
./mvnw clean package -DskipTests
```

### 7.2 构建前端

```bash
cd frontend
npm ci
npm run build
```

`npm run build` 会先进行 TypeScript 类型检查，再执行 Vite 生产构建。构建结果位于：

```text
frontend/dist
```

同域部署时不需要设置 `VITE_API_BASE_URL`，浏览器会访问当前域名下的 `/api`。前后端分离到不同域名时，需要在构建前设置完整后端地址：

Windows PowerShell：

```powershell
$env:VITE_API_BASE_URL="https://api.example.com"
npm run build
```

Linux：

```bash
VITE_API_BASE_URL=https://api.example.com npm run build
```

`VITE_API_BASE_URL` 会写入前端构建产物，修改后必须重新构建。

## 8 Linux 生产部署

### 8.1 服务器目录

```text
/opt/eleme/backend/backend-0.0.1-SNAPSHOT.jar
/var/www/eleme/                         前端 dist 内容
/etc/eleme/backend.env                  后端环境变量
```

创建运行用户和目录：

```bash
sudo useradd --system --home /opt/eleme --shell /usr/sbin/nologin eleme
sudo mkdir -p /opt/eleme/backend /var/www/eleme /etc/eleme
sudo chown -R eleme:eleme /opt/eleme
```

复制后端 JAR 和前端静态文件：

```bash
sudo cp backend/target/backend-0.0.1-SNAPSHOT.jar /opt/eleme/backend/
sudo cp -r frontend/dist/. /var/www/eleme/
sudo chown -R eleme:eleme /opt/eleme/backend
sudo chown -R www-data:www-data /var/www/eleme
```

### 8.2 配置 systemd

创建 `/etc/systemd/system/eleme-backend.service`：

```ini
[Unit]
Description=Eleme Backend
After=network.target mysql.service

[Service]
Type=simple
User=eleme
Group=eleme
WorkingDirectory=/opt/eleme/backend
EnvironmentFile=/etc/eleme/backend.env
ExecStart=/usr/bin/java -jar /opt/eleme/backend/backend-0.0.1-SNAPSHOT.jar
Restart=on-failure
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now eleme-backend
sudo systemctl status eleme-backend
```

查看日志：

```bash
sudo journalctl -u eleme-backend -f
```

### 8.3 配置 Nginx

创建 `/etc/nginx/sites-available/eleme`：

```nginx
server {
    listen 80;
    server_name example.com;

    root /var/www/eleme;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`proxy_pass` 后不要添加结尾斜杠。这样 Nginx 会保留 `/api` 路径，与后端的 `/api` 上下文路径一致。

启用配置并检查：

```bash
sudo ln -s /etc/nginx/sites-available/eleme /etc/nginx/sites-enabled/eleme
sudo nginx -t
sudo systemctl reload nginx
```

Vue Router 使用 History 模式，因此 `try_files $uri $uri/ /index.html` 不能省略。否则直接访问 `/orders`、`/merchant-center` 等前端路由时会返回 404。

### 8.4 配置 HTTPS

生产环境应启用 HTTPS。使用 Certbot 的常见方式如下：

```bash
sudo certbot --nginx -d example.com
```

证书签发后检查自动续期：

```bash
sudo systemctl status certbot.timer
sudo certbot renew --dry-run
```

## 9 发布和更新流程

发布顺序：

1. 备份数据库。
2. 拉取经过审核的目标分支或发布标签。
3. 检查是否有数据库结构变更；如有，先准备可回滚的迁移脚本。
4. 执行后端测试和前端类型检查。
5. 构建后端 JAR 和前端 `dist`。
6. 备份当前 JAR 和前端静态文件。
7. 替换后端 JAR，重启后端并验证公开接口。
8. 替换前端静态文件，重新加载 Nginx。
9. 完成登录、店铺列表、下单和商家中心的冒烟测试。

更新后端：

```bash
sudo systemctl stop eleme-backend
sudo cp backend/target/backend-0.0.1-SNAPSHOT.jar /opt/eleme/backend/
sudo chown eleme:eleme /opt/eleme/backend/backend-0.0.1-SNAPSHOT.jar
sudo systemctl start eleme-backend
```

更新前端：

```bash
sudo rsync -av --delete frontend/dist/ /var/www/eleme/
sudo chown -R www-data:www-data /var/www/eleme
sudo nginx -t
sudo systemctl reload nginx
```

`rsync --delete` 会删除目标目录中构建产物之外的文件，因此目标必须明确为 `/var/www/eleme/`，不要指向更高层目录。

## 10 部署验证

### 10.1 服务检查

```bash
curl -i http://127.0.0.1:8080/api/tastes
curl -i http://example.com/api/tastes
curl -I http://example.com/
```

检查结果：

- 后端 `/api/tastes` 返回 HTTP 200 和 JSON 数据。
- 通过 Nginx 访问 `/api/tastes` 也返回 HTTP 200。
- 首页返回 HTTP 200 和 HTML。
- 直接访问 `/orders` 等前端路由时返回前端页面，而不是 Nginx 404。

### 10.2 冒烟测试

每次发布检查这些功能：

1. 普通用户注册、登录和退出登录。
2. 店铺列表、店铺详情和菜品库存显示。
3. 地址新增、编辑和删除。
4. 购物车数量修改、结算、下单和模拟支付。
5. 用户订单列表和订单详情。
6. 商家订单管理、菜品管理和店铺资料编辑。
7. 删除账户和登录失效后的页面跳转。

## 11 常见问题排查

### 11.1 后端无法连接数据库

常见日志包括 `Access denied`、`Communications link failure` 或 `Unknown database 'elm'`。

检查：

```bash
mysql -h 127.0.0.1 -u eleme_app -p elm
systemctl status mysql
```

确认数据库已创建、账号有权限、环境变量生效，并检查 MySQL 是否只监听了错误的网络地址。

### 11.2 前端请求返回 404

- 开发环境检查后端是否监听 `8080`，以及前端是否通过 `npm run dev` 启动。
- 生产环境检查 Nginx 的 `/api/` 代理是否保留了 `/api` 前缀。
- 不要把 `proxy_pass` 写成 `http://127.0.0.1:8080/`，否则可能移除路径中的 `/api/`。

### 11.3 刷新前端页面返回 404

检查 Nginx 的站点根路径中是否包含：

```nginx
try_files $uri $uri/ /index.html;
```

### 11.4 登录后仍提示未登录

- 检查登录响应是否返回令牌。
- 检查后续请求是否携带 `Authorization: Bearer <token>`。
- 确认 `APP_JWT_SECRET` 在服务重启前后没有被意外更换。
- 当前实现是单会话令牌，新设备重新登录会使旧令牌失效。

### 11.5 参数格式错误或枚举值非法

检查请求中的枚举字段是否使用数字编码：

- 性别：`0`、`1`、`2`
- 用户角色：`0`、`1`、`2`
- 门店状态：`-1`、`0`、`1`
- 菜品状态：`0`、`1`
- 订单状态：`-1`、`0`、`1`、`2`

### 11.6 中文乱码

- 数据库和连接统一使用 `utf8mb4`。
- 导入 SQL 时增加 `--default-character-set=utf8mb4`。
- Nginx 通常会根据前端文件返回 UTF 8；如响应头异常，可增加 `charset utf-8;`。

### 11.7 端口被占用

Windows：

```powershell
Get-NetTCPConnection -LocalPort 8080
Get-NetTCPConnection -LocalPort 5173
```

Linux：

```bash
sudo ss -lntp | grep -E ':8080|:5173|:80|:443'
```

## 12 安全和上线限制

公网部署前检查：

- 替换仓库中的默认数据库密码和 JWT 密钥。
- 为应用创建最小权限数据库账号，不使用 MySQL `root` 账号运行。
- 不把 `/etc/eleme/backend.env`、数据库备份、日志和证书私钥提交到仓库。
- 启用 HTTPS，并限制服务器防火墙只开放必要端口。
- 演示 SQL 包含测试账号和明文示例密码，不应直接作为生产账号数据使用。
- 当前用户服务仍以明文方式比较密码。完成密码哈希存储和迁移前，不建议将系统用于真实用户或生产业务。
- 当前跨域配置较宽松。同域部署不依赖跨域；若采用跨域部署，应限制允许的前端域名。
- 生产环境应关闭 MyBatis SQL 控制台输出，避免日志包含业务数据。

## 13 备份和回滚

发布前备份数据库：

```bash
mysqldump -u eleme_app -p --single-transaction --routines --triggers elm > elm-backup.sql
```

保留上一版本的 JAR 和前端目录，例如：

```text
/opt/eleme/releases/20260916/backend.jar
/opt/eleme/releases/20260916/frontend/
```

回滚时先停止后端，恢复上一版本的 JAR 和前端文件，再启动服务并执行部署验证。若新版本修改过数据库结构，使用发布前准备的回滚脚本或数据库备份，不能删除生产数据库后重建。
